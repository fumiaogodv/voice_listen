# 笔记序号规范（N2S 朗读格式约定）

> 本文档告诉你：**笔记怎么写，程序才能正确分条、读对编号、读出好听的停顿。**
> 一句话原则：**每条知识点独占一行，用「数字 + 英文点号」开头，编号从 1 开始连续递增。**

---

## 1. 为什么需要规范

程序不是"读一整篇文字"，而是把你的笔记**拆成一条一条的知识点**，每条单独转语音、再拼起来。拆分靠的是**行首的编号**。所以：

- 编号写得好 → 每一条读得清、编号读成"第一条/第二条"、条与条之间有停顿
- 编号写错 → 可能整段糊在一起，或者编号读成奇怪的东西

---

## 2. 标准格式（照抄即可）

每条知识点**一行**，行首是「数字 + 英文点号 `.` + 一个空格」，编号从 1 连续递增：

```text
1.进程是程序的一次执行过程，是系统进行资源分配和调度的基本单位

2.线程是进程内的一个执行单元，是CPU调度的基本单位

3.进程间通信方式包括管道、消息队列、共享内存、信号量、套接字等
```

**读出来效果**：`第一条。进程是程序的一次执行过程…… 第二条。线程是…… 第三条。进程间通信方式包括……`

---

## 3. 编号分隔符支持哪些

程序识别以下几种编号写法，效果相同（都读成"第N条"）：

| 写法 | 示例 | 说明 |
|---|---|---|
| 数字 + 点 | `1.xxx` | ✅ 推荐 |
| 数字 + 顿号 | `1、xxx` | ✅ 可用 |
| 数字 + 右括号 | `1)xxx` | ✅ 可用 |
| 数字 + 全角点 | `1．xxx` | ✅ 可用 |

> 建议统一用 `1.`（数字 + 英文点号 + 空格），最不容易出错。

---

## 4. 没有编号的补充行怎么处理

如果某条知识点的**补充说明**想跟在它后面（不想单独占一条编号），直接**另起一行但不写编号**，程序会自动把它**并进上一条**一起读：

```text
5.设备控制器有三部分，寄存器组，设备接口，IO逻辑
IO逻辑实现设备控制功能
```

**读出来效果**：`第五条。设备控制器有三部分，寄存器组，设备接口，IO逻辑。IO逻辑实现设备控制功能`

> 也就是说：**只有带编号的行才会"断条"**，不带编号的连续行都会并到上一条。

---

## 5. 必须注意的坑

### 5.1 编号要连续，不要跳号

```text
1.xxx
2.xxx
4.xxx   ← 错误！跳过了 3
```

跳号不会报错，但读出来会是"第一条、第二条、第四条"，听感奇怪。**建议保持 1、2、3、4 连续。**

### 5.2 一行只写一条知识点

```text
1.进程是程序的一次执行过程，是系统进行资源分配和调度的基本单位。线程是进程内的执行单元  ← 不好
```

两条知识点塞一行，程序会当成一条，不会拆开。**一条知识点一行。**

### 5.3 不要用「第X条」这种中文开头

```text
第一条、进程是程序的一次执行过程  ← 不要这样写
```

程序只认**阿拉伯数字**开头，中文"第一条"不会被识别为编号，整行会被当普通文本，不读编号前缀。

### 5.4 不要在正文里乱用 `**` 等 Markdown 符号

```text
1.**进程**是程序的一次执行过程  ← ** 会被自动去掉，不影响，但没必要加
```

程序会自动清理 `**`、`*`、反引号、`#` 等符号，但为了朗读干净，**建议正文就用纯文字**，别加格式符号。

---

## 6. 技术参数（可调，一般不用动）

| 项目 | 默认值 | 说明 |
|---|---|---|
| 编号转写 | 开 | `1.` → 读"第一条"；可在 `config.py` 里 `READ_NUMBER_AS_ORDINAL=0` 关闭（改回读"一"） |
| 条间停顿 | 0.6 秒 | 每条知识点之间的静音，`SEGMENT_GAP_SEC` 可调 |
| 单条长度上限 | 800 字 | 超过会自动在句末切块，不影响听感 |

---

## 7. 完整示例（一个规范的文件）

```text
1.进程是程序的一次执行过程，是系统进行资源分配和调度的基本单位

2.线程是进程内的一个执行单元，是CPU调度的基本单位

3.进程间通信方式包括管道、消息队列、共享内存、信号量、套接字等

4.进程的状态包括就绪、运行、阻塞三种基本状态
调度程序负责在就绪队列中选择进程投入运行
```

**规则小结**：编号从 1 连续递增、每条一行、补充说明不带编号另起行、正文纯文字。
